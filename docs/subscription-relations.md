# 多付款人和多分类

本分支在官方 v5.10.4 的多对多模型基础上做兼容集成。迁移 `000084.php` 新建 `subscription_payers`、`subscription_categories` 并回填既有主引用，不修改价格、付款记录或付款快照。多付款人指当前账号名下的家庭成员，不授予其他 Wallos 登录账号访问权。

## 数据及客户端约定

- `payer_ids`、`category_ids` 为有序、非空的 ID 数组，最多 100 项，第一项为主引用，重复 ID 去重。每个 ID 必须是正整数，且属于当前账户。
- 保留旧的 `payer_user_id`、`category_id`，使旧客户端继续读取主引用。
- 新建可只传两个数组；主引用由首项产生。
- 更新时省略关系字段保留完整列表；只传旧标量会将该项提升为主引用，保留其他已分配项。
- 显式传数组会替换整个对应列表。同时传数组和标量时，标量必须等于首项，否则拒绝请求。
- 网站编辑表单使用可访问的原生多选控件，恢复完整选择和主引用顺序。桌面键盘支持 Ctrl/Cmd、Shift 多选，移动设备使用浏览器原生选择器。
- 关联数据参与 MCP 并发版本判断，由 MCP 共同业务层执行权限、防重、事务及审计。

网页、异步列表、订阅详情、日历和导出显示完整分配。旧读取 API 保留标量名称字段，并在订阅列表增加 ID 数组与名称数组。分类和付款人筛选匹配任何一项关联，使用 EXISTS 防止联表放大订阅数量。排序仍按主引用分组。

复制订阅保留关联，移入回收站与恢复保留关联，永久删除清理关联。被次级关联引用的分类或成员同样不能删除。数据库触发器覆盖旧标量新增、更新和永久删除路径，兼容关闭外键的历史维护流程。完整数据库备份和恢复包含两张表及触发器。

## 费用和提醒

费用分别在付款人维度和分类维度等分。一个 120 元订阅分给两个付款人，每人的月成本是 60；分入两个分类，每类也各 60。总订阅成本仍为 120。同一条订阅同时筛选其中一个付款人和一个分类时，显示两个维度交集份额 30。

实际付款历史仍是一条原金额交易。统计页筛选时，对用于显示的付款副本按当前分配计算份额；数据库中的历史实付金额、币种及汇率快照保持不变。当前分类或成员分配调整后，分类统计会随当前分配变化；它不构成历史分摊账本或家庭成员之间的结算系统。

邮件续费和取消提醒发送给有邮件地址的各付款人；次级付款人没有地址时跳过，避免重复发到账号默认邮箱。其它通知渠道按订阅通知一次，显示完整分类和付款人名称。周期总览继续按账号发送一次。

## 验证

```sh
docker run --rm --entrypoint php -v "$PWD:/work:ro" \
  local-security/wallos-agent:20261103-upstream-final /work/tests/subscription_relations_test.php
```

浏览器回归只允许使用隔离的 `upstream_integration_fixture.php` 测试账号，设置 `WALLOS_UPSTREAM_TEST_URL`、`WALLOS_UPSTREAM_FIXTURE_FILE` 和 `WALLOS_AGENT_TEST_KEY_FILE` 后运行：

```sh
node tests/e2e/subscription_relations_smoke.mjs
```

它真实验证多选创建与编辑、MCP 读回、主次筛选、60/30 费用分摊、原始付款保留、复制和回收站恢复。不得将写入测试指向生产数据。

`tests/subscription_relation_stats_test.php` 直接在五个独立进程、内存数据库中加载实际统计模块，验证无筛选、单付款人、单分类、双维度交集及不属于当前筛选的替代项目：停用节省金额、去重替代费用、滚动预测、周期预算需求按同一份额计算，账号预算数值保持不变。

网页新增、编辑及复制启用 SQLite 异常，事务开始失败时不会继续自动提交。复制时订阅、完整关联、优惠规则和图片元数据在一个写事务内保存；失败时回滚，并清理已追踪的新复制图片。`tests/subscription_relation_atomicity_http_test.py` 需要额外显式指定 `WALLOS_FEATURE_TEST_DB`，脚本验证专用测试账户后，仅对 UUID 命名的临时记录注入次级关联 SQL 故障，检查实际 HTTP 新增、复制及初始付款的整体回滚，并在 finally 删除故障触发器。不能用于生产数据库。
